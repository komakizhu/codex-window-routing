# 个人窗口与 Codex 任务分流

2026-10-31，真实 Mac、两块显示器，固定任务副屏为 Sidecar。

## 问题与修复

只读检查发现：普通 Chrome 的 `Profile 2/Preferences` 已把最后窗口位置记到 Sidecar；当时 Chrome 仅剩本项目保留的副屏工作窗。个人从 Dock 打开 Chrome 时可能复用它。旧 PiP 规则没有批量移动 Chrome，单纯增加窗口白名单不能消除 Chrome 自身的位置记忆。

本次没有修改 Chrome 偏好、用户配置文件或个人页面。新增按用途登记的入口：`automation` 用副屏，`review` / `user` 用打开前用户焦点屏幕；不根据父进程或浏览器名称推断。个人 Chrome 有单独窗口，后台任务结束只把它设置成 Chrome 内部默认窗口，使用官方 `becomeMain()`，不激活 Chrome。

## 尚未验证

- 用户本人从 Dock、Spotlight、应用列表等不同入口打开 Chrome。当前已装真实点击识别，并准备了主屏个人窗口，但模拟检查和 Chrome 内部默认窗口状态不能冒充用户手动验收。
- 用户本人点击 Codex 的“在 Finder 中显示”。只识别已经列出的明确按钮名称；瞬间消失的菜单可能无法识别，失败时不猜测其他 Finder 窗口。
- Chrome 退出后重新启动、跨 Space 和长时间混合使用。个人/任务的原生登记在 Hammerspoon 完整退出后不会自动认领旧窗口；需要重新明确登记。
- Obsidian、Anki、终端等其他原生应用的逐项真实分流与输入冲突测试。

## 范围与恢复

外部开窗模块已加载，仍沿用 `CU副屏` 总开关；不增加新的开机应用。全局 Agent 规则追加了独立分流段落，并备份原文；它要求今后自主外部打开先登记，也明确用户查看走主屏。它不是修改 Codex 内置功能，也不能强制纠正未遵守规则的旧脚本或已运行聊天。

撤销运行 [恢复脚本](../restore_hammerspoon_config.sh)：恢复原始 Hammerspoon 配置，并仅移除本项目全局段落。原配置备份保留在 `~/.hammerspoon/backups/`，本次全局规则备份为 `/Users/example/.codex/backups/AGENTS.md.window-routing-20261031-111952-498618.bak`。

窗口分流无法提供两套键盘和鼠标。当前建议只启用明确登记的后台浏览器路径；不把所有普通应用的新窗口都自动认作 Codex。手动 Chrome 与 Finder 验收结束前，不标记整体验收通过。

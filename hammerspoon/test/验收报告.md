# Codex Computer Use 双显示器规则验收

> 这是加入两种选屏方式前的历史记录。新增设置的当前结果见[选屏模式验收](选屏模式验收.md)。

## 结论

自动规则已经改成按你的定义选屏：当前正在使用的窗口在哪块屏，那块就是“主屏”；另一块就是“副屏”。规则不看 macOS 标记的主显示器，也不看鼠标位置。

代码已经安装并在 Hammerspoon 里重载。焦点在 U27 时，目标是 Sidecar；焦点改到 Sidecar 后，目标也随之改成 U27。两种方向都已检查。Codex 的小预览当前没有打开，因此“切换焦点后，真实预览会自动换到另一屏”还没有实窗验收。

## 屏幕和运行情况

- macOS 15.7，Apple M1 Max，arm64；Hammerspoon 1.1.1，辅助功能权限已开。
- Codex 桌面版 `26.1027.30824`，build `22943`。
- 当前两块屏：U27N3G6R4B（UUID `E761F686-7E3C-41E5-BBEB-3BB07918B7E6`，macOS 标为主显示器）；Sidecar Display (AirPlay)（UUID `532D7571-4385-4C76-AE82-83D54579002B`）。这些名字和 UUID 只用于认屏，不决定你说的主屏、副屏。
- 最后一次检查时，Safari 是前台应用，正在使用的窗口 `790` 在 Sidecar；规则因此把 U27 作为目标。此前焦点在 U27 时，规则选的是 Sidecar。

## 测试结果

| 项目 | 结果 | 实际情况 |
|---|---|---|
| 选屏方向 | 已通过方向检查 | 焦点在 U27 时选 Sidecar；焦点在 Sidecar 时选 U27。最后一次实机读取到的前台 Safari 窗口在 Sidecar，实际目标为 U27。 |
| Codex 小预览 | 部分完成，真实窗口待验收 | 规则仍只处理 Codex 的 `Computer Use` 和 `Computer Use Controls`。此前确实移动过真实预览，但当时用的是固定 Sidecar 规则；Codex 后来把预览放回。新的“跟随当前焦点”规则尚无正在运行的 PiP 窗口可测。 |
| 新开浏览器窗口 | 单次实测有效 | 经你允许后，单独新开了 Safari 窗口 `19922`，移到另一块屏，在新窗口打开 Poe 并刷新。刷新前后输入框为空，“发送”按钮为灰色，没有发送内容。原有 Safari 窗口 `790` 和 `13658` 没有移动。此测试用的是一次性监视，不表示常驻规则会自动接管所有 Safari 窗口。 |
| 个人窗口保护 | 已有窗口未动；通用新窗规则未开启 | 新开窗口的测试没有移动原有 Safari 窗口。常驻规则仍只匹配 Codex 自己的两个窗口，不会搬普通浏览器或 Obsidian 等窗口。 |
| 焦点和输入 | 不能完全隔离 | Hammerspoon 移动窗口本身不会主动激活或置顶窗口。操作期间读到的前台应用和鼠标位置有变化，但无法判断是不是 Computer Use、用户操作或其他应用造成。键盘、鼠标和焦点仍不是完全隔离的两套。 |
| 长时间运行和断屏 | 尚未完整验证 | 重载后自动规则、窗口焦点监听和应用切换监听均已运行。持续数小时、反复回移 PiP 和断开 Sidecar 后的实机测试尚未完成。 |

此前的隔离测试程序有 9 个普通窗口成功移到 Sidecar；这证明 Hammerspoon 的窗口移动接口可用，但发生在本次动态选屏规则之前，不能替代真实 PiP 验收。

## 当前安装

- [自动移动模块](../computer_use_sidecar.lua)只处理 Codex 自己的两个已识别预览窗口。它在当前焦点窗口改变、应用切换、窗口创建/移动和显示器变化时重新判断目标屏。
- 当前按正好两块屏处理；屏幕数量不是两块、找不到焦点窗口或其屏幕时，规则会停手并记日志，不猜目标。
- 自动分配默认开启；菜单栏 `CU副屏 ●` 可暂停或恢复。移动不主动切换应用，不隐藏 PiP。
- Hammerspoon 启动配置 `~/.hammerspoon/init.lua` 未改。本次最后部署前的模块备份在 `/Users/example/.hammerspoon/backups/computer_use_sidecar.lua.focus-check-20261030-220920.bak`。
- [安装与回滚说明](../README.md)已改为你的主屏/副屏定义。可运行 `./restore_hammerspoon_config.sh` 恢复安装前配置。

## 尚未解决

新规则的两种选屏方向和监听器启动状态已经检查通过，但还没有在“你把焦点切到另一块屏”的真实过程中，观察 Codex PiP 自动换屏。现在不会为了测试擅自抢你的焦点。Hammerspoon 只能移动窗口，不能保证 Computer Use 不改变鼠标、键盘或前台应用。

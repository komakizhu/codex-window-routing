# 轻量开窗入口

2026-11-02。本机只使用现有 Hammerspoon，不安装虚拟机或新的常驻应用。

本任务的最新结果见 [来源分流验收](test/窗口来源与主副屏分流验收.md)，重点是用户确认的主副屏及开窗来源区分。[命令行与调用前检查](../routing/README.md) 已安装并经用户信任；真实绕行拦截及合法开窗均已复测通过。此前 [输入复查](test/窗口持续保护与输入复查.md) 未通过，不作为本轮完成条件；Codex 本身支持后台独立光标，不能因这次失败推断平台没有此能力。此前经用户授权安装的功能已验证；本次 0.3.0 定稿同步项目与 App 版本，不重新安装。

## 当前范围

- Codex 的任务窗口使用 `automation`，读取用户设置的固定副屏 UUID，或使用用户焦点屏幕的另一块屏幕。
- 只有用户本人点击查看入口，或明确要求“在我当前屏打开”时，才使用 `review` / `user`，并提供 `userRequestedMain=true`。Agent 自己创建的测试、预览、状态窗均使用 `automation`；不能因为打算给用户看就擅自当作个人开窗。没有明确的主屏查看授权时，入口拒绝 `review` / `user`。
- 个人查看记录打开前的用户屏幕。程序自行激活应用不会改变这个记录；鼠标经过不算切屏。
- 初始化只加载现有的选屏/PiP 模块和新的 `window_gateway.lua`。旧 Dock/菜单推测路由和全局诊断观察器不再自动加载。
- 新入口只管理本次新建、明确登记的窗口，不接管、恢复默认、激活或移动旧个人窗口。
- 这是 Agent 调用入口，新的 hook 在 Codex 工具执行前约束常见绕行；它不接管个人 Dock/Spotlight，也不是 macOS 级拦截。旧脚本和 Codex 自身查看按钮不能只凭规则声称已覆盖。

## 开关

菜单栏 `CU副屏 ●` → `暂停自动分配` / `开启自动分配`。同一开关控制新入口和 PiP 位置分配。

菜单内仍可选择 `固定使用指定副屏` 或 `跟随焦点，使用另一块屏`。不按鼠标停留位置或 macOS 主显示器判断。

屏幕断开、暂停、窗口编号不明确或检查失败时停止相应步骤，不回退到主屏，不反复移动或抢回焦点。

实时状态用 `hs ./hammerspoon/window_status.lua` 查询。它只读实际开关，区分安全暂停、自动分配开关、模块是否加载及入口是否可用，不改变设置。旧故障记录中的暂停状态只代表记录当时。

## 调用

统一入口是 `hs._codexWindowGateway.open(intent, application, options)`；暂时兼容 `hs._codexExternalWindowRouter` 名称，但不要再加载旧模块。

Finder：

```lua
local result, err = hs._codexWindowGateway.open("automation", "finder", {
    directory = "/absolute/task/folder",
})
```

Finder 创建新窗口后显式设置这个新窗口的 target 和 bounds。实机发现仅在 make-properties 中给属性可能仍打开“电脑”页面，且位置会被记忆覆盖。入口核对实际目标目录的文件标识，并记录首次检测位置和是否进行了事后移动；不把窗口搬过去当作任务内容已正确。

Chrome：

1. 按 Computer Use 的说明选择 Chrome 连接并命名任务。连接不可用就停止，不通过原生 `getApp` 启动个人 Chrome。
2. 从 management 的 `windows.getAll({populate:false})` 取得当前窗口编号，读取当前连接的 `extensionInstanceId`。
3. 调用 `open("automation", "chrome", {browserBaselineIDs={...}})`，拿到当次 request。
4. 将 `browser/chrome_work_window.mjs` 的函数定义按 Computer Use 规则加载到其运行环境，调用 `createChromeFromGateway(browser, request, extensionInstanceId)`。
5. 将它返回的 `proof` 交给 `finishBrowser(requestID, proof)`。此处使用浏览器直接返回的编号，不因用户继续打字而猜测 Accessibility 窗口。
6. 任务页仍使用原帮助函数的 `runOnSideScreen` 检查；只操作精确的新标签，不复用个人标签。任务结束关闭自己的临时标签。

取得明确主屏查看授权时，使用 `review` 并在 options 中加入 `userRequestedMain=true`。不能为了测试个人开窗而自行加入这个授权。Chrome 的个人查看窗口不自动绑定成临时任务标签。打开位置正确不代表允许激活。

Obsidian：

```lua
local pending, err = hs._codexWindowGateway.open("automation", "obsidian", {
    protectedDirectories = {"/absolute/personal/vault"},
})
-- 异步结果：gateway.results[pending.requestID]
-- 成功还须有 backgroundBootstrapInstalled=true。
-- 只按 pending.pid / result.windowId 操作，Computer Use 连接 pending.workerApp 完整路径。
```

此工厂只创建独立配置和空白测试库，不打开个人库，不复制或改动个人插件。需要使用真实笔记库属于另一项授权，不能借测试完成。

后台副本从本机官方安装的 Obsidian 制作，原应用只读。它在启动原程序之前，把自己的窗口显示改为不激活显示，并禁止程序自行要求前台；没有反复抢回焦点。副本具有独立 Bundle ID，自己的存储身份和 CLI 连接，不接管个人实例。工厂不再要求 allowForeground。安装与撤销见 [后台副本说明](../obsidian/README.md)，实际结果见 [后台输入验收](test/Obsidian后台输入验收.md)。

窗口出现后必须检查 gateway.results[pending.requestID].ok 及 backgroundBootstrapInstalled；失败不能继续点击。只能用返回的 workerApp 完整路径连接 Computer Use，不能使用个人 Obsidian 的 Bundle ID 或泛用名称。副本的多个窗口都属于自己的空白库，后续窗口沿用启动时选定的副屏位置。每次新任务重新取选屏结果。

本分支的新副本要求 `backgroundProtocolVersion=1`，旧副本会返回 `worker_update_required`。每个任务记录原生显示器编号及完整边界；创建时先隐藏窗口，确认屏幕仍匹配后才显示。暂停、控制文件丢失、断屏或布局变化会隐藏本任务窗口，重新连接不会自行恢复。启动未完成的失败任务只结束自身进程；已经启动的任务保留数据并暂停显示。

原生操作前后可调用 `gateway.guardNative(requestID, windowId, pid)` 检查准确归属和位置，但它不能阻止两次检查之间的短暂激活，不能当作输入隔离。当前实机输入复查未通过，日常笔记任务应优先使用文件或应用接口。

系统授权弹窗、外部链接及个人插件尚未测试；不能由这些测试推出所有 Obsidian 操作都不会抢输入。个人常用 Obsidian 未修改，直接启动原应用不走此后台路径。

Obsidian 的当前安装器即使使用独立配置也访问共享 CLI socket。副本把这一个路径改为自己的连接；启动时还额外禁止主进程修改个人连接和配置。精确列出的 helper 不继承这层额外限制，以保留原应用自身的进程启动方式；没有给启动命令追加关闭沙箱的参数。Obsidian 自身的 renderer 参数和原安装器一致，不应将这层保护称为完整的系统隔离。`sandbox-exec` 已被 Apple 标为 deprecated；将来不可用时停止测试，不以无保护方式启动。

## 恢复

本轮同步只涉及 Hammerspoon 的加载入口和新模块，没有重新安装登录启动项。改动前的文件和窗口/选屏状态已备份到本机 Hammerspoon backups 下的本轮目录，具体路径见本轮验收报告。

恢复本轮前的文件之前，先暂停自动分配，核对文件是否仍为本轮版本，避免覆盖后来的改动。旧路由原本会处理个人开窗，回退后仍不应未经检查直接开启。原项目的整体恢复脚本保留，见 `restore_hammerspoon_config.sh`。

本轮没有执行 Git 提交、合并或推送。
